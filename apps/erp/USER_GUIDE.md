# ShipYard 초보자 매뉴얼

[현재 ERP 화면별 매뉴얼과 업무 적합성 점검](docs/ERP_WORKFLOW.md)

[HTML 업무 매뉴얼](docs/ERP_WORKFLOW.html)은 ERP 서버의 `/guide`에서도 열 수 있습니다.

[ShipYard 열기](http://127.0.0.1:8001/) — 관리자에게 받은 아이디로 로그인합니다.

**처음이라면**: 업무는 1~10단계(기준 준비 → 일정·블록 계획 → 12주 계획 발행 → 자재 부족 확인 → 구매·입고 → 작업지시 → 자재 출고 → 실적·검사 → 품질 확인 → 블록 이동·탑재)로 이어집니다. 왼쪽 메뉴의 숫자 배지와 각 화면 위쪽의 단계 표시줄이 지금 단계를 알려 줍니다. 화면마다 **이 화면 사용법**을 펼치면 할 일 순서와 이전/다음 단계 버튼이 있습니다. 저장하면 초록색 **이어서 할 일** 버튼이 나타나고, 누르면 값이 채워진 다음 단계 입력 창이 열립니다. 상태 배지는 빨강(조치 필요), 주황(대기), 초록(완료)입니다. 용어는 표 머리글에 마우스를 올리거나 오른쪽 위 **업무 안내·용어**에서 확인합니다.

**업무 홈 보는 법**: 맨 위 **조선소 공정 지도**는 배 한 척이 만들어지는 6단계(계획·설계 → 주간 계획·자재 → 가공·블록 조립 → 품질 검사 → 블록 이동·탑재 → 의장·진수·인도)입니다. 단계 아이콘의 숫자는 쌓여 있는 건수이고, 빨간 테두리는 바로 조치할 곳입니다. 단계 안의 칩(번호 = 업무 단계)을 누르면 해당 화면이 열립니다. **지금 막혀 있는 곳**은 건수가 있는 항목만 원인과 함께 보여 주고, 나머지는 "이상 없음"에 모입니다. **데이터 추적**에 REQ·PO·작업지시·Lot·블록·NCR 번호를 넣으면 계획부터 블록 이동까지 연결된 기록이 **흐름 한눈에 보기**로 열리고, 부족·미입고·실적 누락처럼 멈춘 곳이 **확인이 필요한 곳**에 나옵니다. 처리할 업무 목록의 **흐름 추적** 버튼도 같은 화면을 엽니다.

왼쪽 메뉴에서 업무를 선택하고 화면 위쪽 탭에서 목록을 바꿉니다. 처음에는 조회 호선을 **전체 호선**으로 두거나 예시 호선 **H101**을 선택하세요. 문서 번호를 누르면 원천 문서와 다음 작업을 볼 수 있습니다. 목록은 검색, 상태, 기간, 정렬로 좁힐 수 있습니다.

## SN2036 가상 실습

조회 호선에서 **SN2036**을 선택합니다. **중일정 · 선체**에서 211P의 구성 블록 211A·211B와 선행 탑재 블록 310C를 확인하세요. **블록 준비 현황**에서 211P를 펼치면 도면 출도 근거, 검사 보류와 선행 블록 사유를 볼 수 있습니다. **구매·입고 → 발주**에는 AH36 후판 16장 중 8장이 합격 입고되고 8장이 남은 예시가 있습니다. **자재 출고 → 수불부**에서 SN-AH36-20을 선택하면 창고 기초재고 36장과 입고 8장을 확인할 수 있습니다. 아래의 H101은 구매요청부터 시작하는 별도 실습입니다.

## 1. 조선소에서는 무엇을 만드는가

**호선**은 건조할 선박 한 척을 관리하는 단위입니다. **블록**은 선체를 여러 부분으로 나눠 만든 구조물입니다. 작업장에서 강재를 절단·조립하고, 블록 상태에서 배관이나 장비를 설치하는 **선행의장**과 도장을 진행합니다. 이후 큰 블록을 도크에서 선체에 결합하는 **탑재**를 합니다. 선박이 물에 뜨는 **진수** 이후에는 안벽에서 남은 의장 작업을 하고, 시운전과 인도를 진행합니다. 세부 순서와 준비 조건은 호선과 조선소에 따라 달라집니다.

| 현장 질문 | ShipYard에서 보는 곳 |
|---|---|
| 언제 진수하고 인도하는가 | **대일정 → 호선 주요 일정** |
| 이번 12주에 무엇을 해야 하는가 | **소일정 (주간·일일) → 12주 롤링·주간 발행** |
| 무엇을 먼저 만들고 어느 시설에 탑재하는가 | **중일정 · 선체 → 블록 구성 / 탑재 선후행 / 탑재 계획** |
| 강판이 부족한가, 언제 살 수 있는가 | **자재 소요계획 (MRP) → 자재 부족** |
| 작업장 제약을 고려하면 언제 작업할 수 있는가 | **소일정 (주간·일일) → 제약 일정 제안** |
| 오늘 무엇을 출고하고 어떤 작업을 끝냈는가 | **자재 출고**, **작업지시·실적**, **품질 검사** |
| 블록이 어디에 있고 왜 탑재를 준비하지 못했는가 | **블록 이동 → 블록 위치**, **중일정 · 선체 → 블록 준비 현황** |

## 2. 계획을 읽고 작업지시 만들기

1. **기준정보**에서 호선, 블록, 창고와 작업장, 도크·안벽이 등록되어 있는지 봅니다. **워크센터**에는 작업 가용시간을 등록하고 실제 시설을 연결합니다.
2. **대일정 → 호선 주요 일정**에서 착공·기공·진수·시운전·인도를 등록합니다. **기준일**은 최초 비교 기준, **예정일**은 현재 예상, **실제일**은 수행한 날짜입니다. 날짜가 바뀌면 사유를 넣고 **일정 변경 이력**을 확인합니다.
3. **소일정 (주간·일일) → 공정 목록**에 공정을 등록하거나 예정일을 갱신합니다. **12주 롤링·주간 발행**에서 시작 월요일을 지정해 발행합니다. PLAN 번호가 있는 발행본은 발행 당시의 상태를 보존합니다.
4. 발행본을 펼쳐 해당 공정의 **작업지시**를 누릅니다. 공정과 계획 번호가 채워집니다. 주간 작업지시를 만들고 필요하면 같은 공정·같은 주의 일일 지시를 연결합니다.

**MRP**는 소요일에 자재가 얼마나 부족할지 계산합니다. **APS**는 작업장 가용시간과 선행 공정, 자재 부족을 고려한 일정 제안입니다. 제안 결과를 읽은 뒤 계획 담당자가 예정일을 갱신합니다.

## 3. 모의 강판으로 구매부터 실적까지 실습

예시 DB에서 **H101 → A2 가공·조립 → REQ1 선체용 강판**이 연결됩니다. 처음 구성의 소요는 **25장**, 후판 창고 STORE의 재고는 **20장**입니다. 화면 데이터가 이미 바뀌었다면 아래의 5장 대신 현재 부족량을 사용하세요. 등록은 DB에 기록되므로, 흐름만 연습할 때는 각 등록 창에서 내용을 확인하고 닫으세요.

| 순서 | 화면에서 할 일 | 확인할 결과 |
|---|---|---|
| 1. 소요 확인 | **MRP → 자재 부족**에서 REQ1의 **구매요청 등록**을 엽니다. | 소요 번호와 부족 수량 5장이 채워집니다. |
| 2. 발주 | 구매요청을 저장한 뒤 **구매·입고 → 구매요청**에서 발주를 엽니다. 공급업체와 납기일을 지정합니다. | 발주 번호와 미입고 잔량이 표시됩니다. 납기가 소요일 이내면 발주 잔량이 MRP의 예정 공급에 반영됩니다. |
| 3. 입고·검수 | 발주에서 **입고·검수 등록**을 열고 실제 입고일, 창고 STORE, 수량과 판정을 입력합니다. | 합격분만 재고에 들어옵니다. 일부만 합격 입고하면 나머지는 미입고 잔량으로 남습니다. |
| 4. 자재 출고 | A2의 미완료 주간 지시를 선택하고 **자재 출고**에서 REQ1, 출발 창고 STORE, 수량을 입력합니다. | A2의 워크센터를 통해 도착 시설 SHOP을 찾습니다. 수불부에서 출고 번호, 차감 수량, 처리 후 잔량을 확인합니다. |
| 5. 실적·검사 | **작업지시·실적**에서 실제일, 작업 결과, 검사 판정을 등록합니다. 일일 지시가 있으면 일일 실적부터 처리합니다. 기록이 있으면 작업 시설·장비·교대·작업 시각·수량과 단위·공수·검사 근거를 입력합니다. | 합격 실적은 공정 필수 자재 출고를 확인합니다. 작업지시마다 생산 Lot No(`PLOT-`), 등록할 때마다 실적 문서 번호(`RES-`)가 발급됩니다. 같은 지시의 재검사는 기존 생산 로트로 조회합니다. |

입고는 **앞으로 들어올 수량**과 **검수까지 마쳐 실제로 들어온 수량**을 구분해서 보세요. 출고 가능 여부는 선택한 창고의 실제 재고가 결정합니다. **자재 출고 → 수불부**에서 입고·출고 번호를 누르면 원천 문서를 추적할 수 있습니다.

실적 번호를 누르면 작업지시, 공정, 계획 생산 시설, 등록된 실제 작업 시설과 자재 출고 로트를 확인할 수 있습니다. 주간 지시와 일일 지시는 각각 관리용 생산 로트를 가지며 주간 집계와 일일 수량·공수를 합산할 때는 중복을 확인하세요. 강재 Heat No와 밀시트는 출고 로트를 통해 확인합니다. 작업 시각은 한국시간으로 입력하며, 야간 교대는 실제 종료일을 실적일로 입력합니다.

| 조선소 생산 단계 | ERP에서 확인할 문서와 주요 컬럼 |
|---|---|
| 설계·구매 | 호선과 블록, 도면·리비전, EBOM·MBOM, 품목과 단위, 소요일, 발주·입고 문서, 강재 Heat No와 밀시트. |
| 절단·가공과 소·중·대조립 | 작업지시, 생산 로트, 블록과 조립 단계, 워크센터·작업 시설, 작업 교대·시각, 산출 수량·단위, 투입 공수, 치수·용접 검사 근거. 세부 조립 단계와 누적 공수는 **블록 조립·공수**에서 관리합니다. |
| 선행의장·도장 | 블록별 배관 스풀·기자재·전장품의 입고·설치·검사 이력, 대상 블록과 작업 시설, 공수, 도장·검사 근거. |
| 선행탑재(PE)·도크 탑재 | 구성 블록, 적치 위치, 이송 장비와 출발·착지 기록, 탑재 선후행, 도크, 크레인 배정, 탑재일과 검사 판정. |
| 진수·안벽의장 | 호선 진수일, 선석 배정, 이동 지점과 예정·실적일, 구역별 후행의장, 설치·검사 기록. |
| 시운전·인도 | 호선 주요 일정, 검사·시험 계획(ITP), 검사 근거, 미결 NCR·펀치 및 종결 기록, 인도 실적일. |

작업지시·실적 목록에서는 상위 공정 분류와 블록 마스터를 함께 조회할 수 있습니다. 탑재, 이동, 검사 등 별도 화면에 있는 기록은 각 원천 문서에서 관리합니다.

## 4. 블록 탑재 준비 확인

1. **블록 구성**에서 상위 블록과 그 블록을 만드는 구성 블록을 연결합니다. **탑재 선후행**에서는 먼저 탑재할 블록과 그 후에 탑재할 블록을 연결합니다.
2. **탑재 계획**에서 블록의 기준일·예정일과 목적 시설을 지정합니다.
3. **블록 준비 현황**에서 B101 같은 블록을 펼칩니다. 도면 출도, 자재 준비, 조립·의장·도장 완료, 검사 승인, 시설 확보, 이동 준비의 상태와 근거를 봅니다. 확인을 마친 항목은 **준비 항목 확인**에서 판정과 문서 번호나 근거를 기록합니다.
4. **블록 이동**에서 이동을 시작하고 실제 도착을 확인한 뒤 이동을 확정합니다. 이동 중에는 기존 확인 위치와 이동 중 상태를 함께 볼 수 있습니다.

5. 블록이 탑재 시설에 도착하면 **블록 조립·공수 → 탑재 검사 실적**에 탑재일과 검사 결과를 기록합니다. 합격 기록은 블록이 그 시설로 이동 확정되어 있고 준비 현황이 ‘준비 확인’일 때만 저장됩니다. 합격하면 준비 현황이 ‘탑재 완료’로 바뀝니다.

‘준비 필요’가 표시되면 먼저 사유를 읽으세요.

| 사유 | 확인할 곳 |
|---|---|
| 도면 출도 미확인 / 최신 도면 … 출도 확인 필요 | 준비 항목 확인(도면 출도). 설계 변경 리비전이 나오면 다시 확인해야 합니다. |
| 미출고 자재 소요 | 자재 출고 |
| 조립 단계 미완료 | 블록 조립·공수 → 공수·진척 실적 |
| 선행의장품 미설치 | 의장관리 → 의장품 이력 |
| 선행 블록 탑재 미확인 | 선행 블록의 **탑재 검사 실적**(합격 기록) |
| 도크 점유 예약 없음 / 탑재 크레인 미배정 / 크레인 용량 부족 | 대일정·소일정의 도크 예약과 크레인 배정 |
| 미결 NCR / ITP 검사 미합격 | 품질 검사 → 부적합(NCR), 검사 계획(ITP) |

## 4-1. 블록 조립 단계와 물량·공수 진척

1. **블록 조립·공수 → 조립 단계**에서 블록마다 필요한 단계(절단·가공, 소조립, 중조립, 대조립, 선행탑재(PE), 탑재)와 워크센터, 계획 공수(M/H)를 등록합니다. 블록에 해당하지 않는 단계는 등록하지 않아도 됩니다.
2. **공수·진척 실적**에 실적일, 투입 공수, **누적** 진척률(%)과 협력사를 입력합니다. 진척률은 줄어들 수 없고, 100%를 입력하면 그 단계의 실제일이 기록됩니다.
3. 앞 단계를 끝내야 다음 단계를 완료할 수 있습니다. 중조립 이후 단계는 구성 블록의 조립 단계가 모두 끝나야 완료됩니다. ‘탑재’ 단계는 탑재 검사 합격 기록이 필요합니다.
4. **물량·공수 진척**에서 블록별 기성 공수(계획 공수 × 진척률), 기성 물량(블록 중량 × 진척률), 생산성(기성/투입)을, 호선별로는 중량 기준과 공수 기준 진척률을 봅니다. **협력사 공수**는 협력사별 투입 공수입니다(협력사를 비우면 ‘직영’).

## 4-2. 도크 예약과 크레인 배정

- **장비 능력**: 기준정보의 장비에 유형, 정격하중(t), 배치 시설을 지정합니다. 블록 이동을 시작할 때 블록 중량이 장비 정격하중을 넘으면 거절됩니다.
- **도크 점유 예약**: 도크별로 호선의 점유 기간을 등록합니다. 같은 도크에 기간이 겹치는 예약은 저장되지 않습니다.
- **휴일 달력**: 휴일은 APS 제안 일정과 탑재 일정 제안에서 제외됩니다(주말은 기본 제외).
- **추가 선행 공정**: APS 작업 제약의 선행 공정 외에 선행 공정을 더 연결합니다. 순환 연결은 거절됩니다.
- **탑재 일정 제안**: 탑재 계획 예정일, 선행 블록 일정, 크레인 정격하중, 크레인당 하루 1회 인양, 휴일을 반영해 탑재일과 크레인을 제안합니다. 계획 예정일은 바꾸지 않습니다.

## 4-3. 강재 로트(히트번호) 추적

1. 합격 입고 후 **강재 추적 → 입고 로트·히트번호**에서 히트번호, 밀시트 번호, 수량을 등록합니다. 입고 목록에서 ‘입고 로트 등록’을 눌러도 됩니다.
2. 자재 출고 후 **출고 로트 배정**에서 어떤 로트를 얼마나 썼는지 기록합니다. 출고 창고에 있는 같은 자재의 로트만 배정할 수 있습니다.
3. **반납·잔재·폐기**: 반납과 잔재는 창고 재고와 수불부에 다시 들어오고, 폐기는 기록만 남습니다.
4. **블록별 강재 추적**에서 블록 → 출고 → 로트 → 히트번호·밀시트·공급업체를 확인합니다. 로트를 배정하지 않은 출고 수량은 ‘로트 미배정’으로 표시됩니다. **블록 트리 자재 소요**는 구성 블록까지 합친 소요와 출고 잔량입니다.

## 4-4. 의장품, 품질(ITP·NCR·펀치), 설계 변경

- **의장 작업**: 왼쪽 의장 → 의장관리 → 작업 패키지에서 의장 단계·공종·처리 상태로 검색합니다. 새 작업계획을 등록하거나 기존 중일정 계획을 선택한 뒤, 상세의 작업지시 발행으로 계통 코드와 계획 수량·단위를 입력합니다. 설치 실적은 회차별 수량과 공수로 등록합니다. 불합격은 재검사 이력으로 남기고 합격 수량만 진척에 반영합니다. 선행 의장은 블록을 지정하며 선내(탑재 후)·안벽 의장은 호선 구역 단위도 가능합니다.
- **착수·탑재 조건**: 작업 패키지에서 같은 블록의 필요한 조립 단계를 지정하세요. 선행 의장 중 탑재 전에 검사 합격이 필요한 작업에만 ‘필수’를 지정합니다.
- **자재 준비**: ‘기존 자재 소요 연결’로 같은 호선·블록의 자재 소요를 연결합니다. 작업 상세에서 구매요청, 발주와 납기, 합격 입고, 출고 및 미출고 상태를 확인하고 문서 번호를 눌러 원본 ERP 목록을 엽니다. 등록한 작업일에 조립 또는 출고 조건이 미충족이면 설치 실적을 저장할 수 없습니다.
- **의장품**: 선행의장품은 설치할 블록을 지정해야 합니다. 진행은 입고 → 설치 → 검사 완료 순서로만 기록됩니다.
- **검사 계획(ITP)**: 블록·공정별 검사 항목과 입회 주체(사내·선주·선급)를 등록합니다. **입회 검사 실적**에 불합격을 기록하면 NCR이 자동 발행됩니다(처리 방안 ‘재작업’).
- **NCR 종결**: 검사 항목에 연결된 NCR은 같은 항목의 재검사 합격 기록이 있어야 종결됩니다.
- **펀치리스트**: 등급 A·B·C로 관리합니다.
- **주요 일정 실적 조건**: 기공에는 첫 블록 탑재 합격, 진수에는 탑재 계획이 있는 모든 블록의 탑재 합격이 필요합니다. 시운전에는 모든 의장품 검사 완료와 A등급 펀치 종결, 인도에는 의장품 검사 완료, 미결 NCR 없음, A·B 펀치 종결, 모든 ITP 합격이 필요합니다.
- **설계 도면**: 최초 출도 후 변경은 ‘설계 변경’ 리비전으로 등록합니다. 새 리비전이 나오면 해당 블록의 ‘도면 출도’를 다시 확인해야 탑재 준비가 풀립니다.

## 4-5. 로그인, 그룹과 메뉴 권한

- **로그인**: 아이디와 비밀번호로 로그인합니다. 5회 연속 실패하면 15분간 잠깁니다. 로그인은 마지막 사용 후 8시간이 지나거나 브라우저 탭을 닫으면 끝납니다. 오른쪽 위에서 **비밀번호 변경**(8자 이상, 문자+숫자)과 **로그아웃**을 할 수 있습니다. 비밀번호를 바꾸면 다른 기기의 로그인은 종료됩니다.
- **첫 관리자**: `./shipyard-postgres create_admin.py --id admin --name 관리자`로 만듭니다. 같은 명령으로 관리자 비밀번호를 재설정할 수 있습니다.
- **그룹**: 관리 → **사용자·권한 → 그룹**에서 그룹을 만듭니다. 처음 시작하면 관리자(ADMIN), 계획(PLAN), 생산(PROD), 구매(PURCH), 품질(QA), 조회(VIEW) 그룹이 자동으로 생깁니다. 기본 그룹은 사용자·권한을 제외한 모든 메뉴를 조회하고, 담당 메뉴만 등록할 수 있습니다.
- **메뉴 권한**: **메뉴 권한** 탭에서 그룹을 고른 뒤 메뉴마다 **조회**, **등록**을 체크하고 **권한 저장**을 누릅니다. 등록을 체크하면 조회도 함께 체크됩니다. 저장 즉시 해당 그룹 사용자에게 적용됩니다. 관리자 그룹은 항상 모든 권한을 가지며 바꿀 수 없습니다.
- **사용자**: **사용자** 탭에서 아이디, 이름, 그룹, 초기 비밀번호로 등록합니다. 목록의 **사용자 정보 변경**으로 이름·그룹·사용 여부를, **비밀번호 초기화**로 비밀번호를 바꿉니다. 사용을 중지하거나 비밀번호를 초기화하면 그 사용자의 로그인이 즉시 끊깁니다. 본인 계정의 그룹 변경·사용 중지와 마지막 관리자 중지는 할 수 없습니다.
- **권한이 하는 일**: 조회 권한이 없는 메뉴는 화면에 나타나지 않고, 등록 권한이 없으면 등록·다음 작업 버튼이 보이지 않습니다. 서버도 같은 기준으로 조회(403)와 저장(403)을 막습니다. 호선·블록·시설·자재·공정 같은 기준 목록은 로그인한 모든 사용자가 조회합니다.
- **이력**: 모든 저장은 **감사 이력**(사용자·작업·문서·입력값, 비밀번호는 `***`)에, 로그인 성공·실패는 **로그인 이력**에 남습니다.

## 4-6. 조회 속도

화면은 연 메뉴에 필요한 목록만 불러옵니다. 서버는 조회 결과를 Redis에 캐시하고, 저장이 일어나면 캐시를 새 버전으로 바꿉니다. 장비 관측, 수불부, 실적·검사, 공수 실적, 감사·로그인 이력처럼 긴 목록은 서버에서 검색·정렬·페이지를 처리합니다(페이지 아래에 ‘서버 검색’ 표시). 이 목록의 검색은 입력을 멈춘 뒤 잠시 후 실행됩니다.

생산 확장 예시 데이터는 `./shipyard-postgres seed_production.py`로 SN2036에 추가합니다.

## 4-7. 설계 BOM(EBOM) → 제조 BOM(MBOM) → MRP (DT-DEMO-01 실습)

예시 데이터: `./shipyard-postgres seed_bom_demo.py` (seed_twin_workflow.py 다음에 실행, 다시 실행해도 중복되지 않음).
조회 호선을 **DT-DEMO-01**로 고른 뒤 단계 표시줄 3·4·6·7단계 순서로 따라갑니다.

1. **관리 › 설계 도면 › 도면 리비전**: B01 `STR R01`, B05 `OFT R01`을 확인합니다. 새 도면 행의 [EBOM 리비전 작성]으로 EBOM을 만듭니다.
2. **설계 도면 › 설계 BOM (EBOM) 리비전 / EBOM 품목 구조**: B01은 보강재 FB 32EA·브래킷 8EA(제작), B05는 밸브 4EA·맨홀 커버 6EA(구매)입니다. 발행된 리비전은 고칠 수 없습니다.
3. **계획 › 제조 BOM (MBOM)**: ①리비전 → ②공정 편성 → ③설계품목 배정 → ④제조 투입품 → ⑤연결 → ⑥발행 전 소요 비교 순서입니다.
   - B01 투입품: 원판 2장(설계 단위 EA와 다른 '장' 단위, 네스팅·수율 84% 근거), 용접 와이어 52kg(설계 대응 없음). B01은 이미 탑재된 블록이라 발행해도 새 소요 없이 완료 작업지시에 "완료 작업 이력 연결"만 남습니다.
   - B05 투입품: 밸브 4EA, 맨홀 커버 6EA, 볼트 세트 8SET(소모품). PE 단계 의장 공정의 자재 소요가 됩니다.
4. **자재 소요계획 (MRP) › 자재 부족**: 맨홀 커버가 4EA 부족합니다. [소요 근거]로 설계품목 O120 → MBOM 투입품 → 소요를 확인하고 [구매요청 등록]을 누릅니다.
5. 설계 변경: 도면 R02 등록 → 이전 EBOM을 복사해 EBOM R02 → 이전 MBOM을 복사해 MBOM R02 → [발행 전 소요 비교] → 발행. 구매요청·출고가 연결된 소요는 그대로 두고, 늘어난 양은 "추가 소요", 줄어든 양은 [설계 변경 조정]으로 남습니다.

규칙: 완료된 공정에는 자재 소요를 추가할 수 없고, 선행 공정이 완료·합격되기 전에는 주간 실적을 합격 처리할 수 없으며, MBOM에 묶인 조립 단계는 투입품이 출고되기 전에 100% 완료할 수 없습니다.

## 5. 막혔을 때 찾는 순서

- 먼저 업무 홈 **데이터 추적**에 막힌 문서 번호를 넣고 **확인이 필요한 곳**을 봅니다. 빨간 점은 부족·불합격·납기 경과, 주황 점은 미입고·미확정·실적 누락입니다.
- 목록이 비어 있으면 **조회 호선**, 검색, 상태, 기간을 확인하고 **조건 초기화**를 누릅니다.
- 발주했는데 출고가 막히면 **입고 검사 합격 여부**, **창고별 재고**, **작업지시 공정과 소요 공정의 일치**, **워크센터와 시설 연결**을 확인합니다.
- 합격 실적이 막히면 실제일 이전의 필수 자재 출고와 하위 일일 지시의 합격 실적을 확인합니다.
- 준비 판정을 기록했는데 계속 보류되면 준비 현황의 남은 공정·자재·선행 블록 사유를 확인합니다.

## 디지털 트윈 연동용 가상 데이터

조회 호선에서 SN2037·SN2038·SN2039를 선택할 수 있습니다. 블록 72개와 이동 39건(완료 36, 진행 중 3), 시간순 장비 관측값 2,235건을 추가했습니다. 블록 15개는 위치 미확인입니다.

Unity는 /api/blocks의 id로 /api/moves의 block을 찾고, 이동 id로 /api/telemetry의 move를 연결합니다. 관측값은 recorded_at 기준으로 재생합니다. 모의 좌표는 공통 야드 평면에서 X/Y 미터, 하중은 모의 톤 값이며 5초 간격입니다. DT-FAB=(20,30), DT-OUT=(160,50), DT-YARD=(290,115), DT-DOCK=(430,170)을 장면의 시설 기준점으로 사용할 수 있습니다. 블록 위치는 ERP의 확인 시설과 상태를 사용합니다. 블록의 세부 좌표, 고도, 회전, 3D 형상 및 센서 실시간 연결은 이 데이터에 포함되지 않습니다.

## 작업 실적과 최초 불합격률

**품질 검사 → 작업 검사**에서 최초 판정, 최신 판정, 기록된 검사 횟수와 최근 실적 번호를 확인합니다. 최초 불합격률은 조회된 작업지시 가운데 최초 판정이 남은 건에 대해 최초 불합격 건수를 나눈 값입니다. 이전 이력의 최초 판정이 확인되지 않는 건과 미검사 건은 분모에서 제외됩니다. 기간은 최초 검사 실제일에 적용합니다. 현재 불합격 행에서 **재검사 등록**으로 같은 작업지시의 새 실적을 남깁니다. 재검사 합격 시 현재 재검사 필요 건수는 줄고 최초 불합격 이력은 유지됩니다.
