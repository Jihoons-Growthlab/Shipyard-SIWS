# SIWS 작업·리뷰·인수인계

## 작업 시작

요청의 완료 조건, 담당 앱, 작업 브랜치 또는 기준 커밋부터 확인한다. 이미 수정된 파일이 있으면 작성자와 담당 범위를 확인하고 기존 변경을 보존한다. Claude와 Codex가 동시에 구현할 때는 작업별 브랜치와 worktree를 사용한다. 기존 공유 작업 폴더에 여러 작업이 섞여 있으면 이관 전에 작업별 범위를 확인한다.

진입 지침은 루트와 앱의 AGENTS.md·CLAUDE.md를 사용한다. 포트와 실행 명령은 [개발 가이드](development.md), API·업무 기준은 [ERP–Twin 연동 기준](../shared/contracts/README.md), Unity 수정 위치는 [작업별 경로](../apps/twin/docs/project-map.md)를 기준으로 삼는다. 요청과 관련된 범위부터 읽는다.

## 구현과 교차 리뷰

SIWS의 기본 역할은 Codex가 앱 간 연결·데이터 연동·통합 검증을, Claude가 섬세한 화면과 상호작용 구현을 맡는 것이다. 작업별로 담당 파일을 먼저 나눈다.

1. 구현 담당이 변경분과 검증 결과를 넘긴다. 작업 브랜치와 기준 커밋, 의도한 변경 범위를 포함한다.
2. 리뷰 담당은 변경분을 먼저 읽은 뒤 필요한 호출부, API 계약과 테스트를 확인한다. 재현 가능한 문제만 파일·줄, 사용자 영향, 검증 방법과 함께 남긴다. ERP 연동 변경은 권한, 계획과 실적의 구분, 호선·블록·시설 ID, 좌표와 시각, Portal·Twin 소비 코드까지 확인한다.
3. 구현 담당이 수정하고 관련 테스트를 다시 실행한다. 완료 기록에는 발견한 사항과 수정 결과, 남은 검증을 남긴다. 배포나 서버 재시작이 요청 범위에 포함되면 그 결과도 기록한다.

## 공통 검증

저장소 루트에서 변경 범위에 해당하는 [검증 명령](../tools/verify)을 실행한다. 여러 범위를 한 번에 지정할 수 있다. 예시는 `tools/verify erp portal`이다.

| 범위 | 명령과 확인 내용 |
| --- | --- |
| ERP | `tools/verify erp`. 임시 SQLite와 메모리 캐시로 ERP 테스트 전체 실행. PostgreSQL·Redis 동작 변경 시 전용 테스트 인스턴스에서 별도 확인한다. |
| Portal | `tools/verify portal`. Python 문법 확인. 화면 변경은 해당 페이지에서 동작을 확인한다. |
| Unity | `tools/verify twin`. EditMode 테스트. 조작이나 화면 배치 변경은 실제 플레이 화면에서 확인하고, 웹 배포 시 WebGL 빌드와 브라우저 로딩을 확인한다. |
| Nginx | `tools/verify nginx`. 실행 중인 Portal을 대상으로 임시 로컬 포트에서 미리보기. 실제 HTTPS를 변경했다면 본인용·친구용 접근 범위도 확인한다. |

## 다음 세션에 넘길 작업 기록

작업별 PR을 사용하면 PR 본문에 기록한다. PR 없이 이어가는 작업은 `docs/handoffs/<작업명>.md` 한 곳에 남기고 다음 담당자에게 경로를 전달한다. 완료된 결정은 관련 명세에 반영한다. 비밀, 개인 접속 정보, 전체 대화 원문은 기록에서 제외한다.

```text
목표와 완료 조건
브랜치·기준 커밋·수정 범위
완료한 변경과 결정 근거
리뷰 결과와 수정 상태
실행한 검사와 결과
미확인 항목과 다음 단계
```

진행 중인 참고 기록은 [모바일 트윈 화면](handoffs/twin-mobile-layout.md)에 있다.
